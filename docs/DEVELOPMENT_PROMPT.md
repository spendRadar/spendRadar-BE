# 개발 공통 프롬프트

일별 거래 기록을 기반으로 소비 전망과 예산·구매 상담을 제공하는 가계부를 개발한다.
사용자가 실제 수입·고정/변동 지출을 CRUD로 입력하며, 정기수입·고정지출 설정은 실제 거래와 구분한다.
Spring Boot + JPA + H2를 유지하고 프론트는 별도 프로젝트에서 REST API로 연결한다.

질문은 GPT-5.4 mini Responses API의 Structured Outputs로 의도·기간·카테고리·금액으로 변환한다.
LLM이 DB를 직접 조회하거나 예측값을 만들지 않는다. 백엔드가 과거 일별 카테고리 지출을 집계해
Python Chronos-2에 전달하고, 모델 결과를 검증한 뒤 실제값·정기 설정과 조합한다.
백엔드가 월 합계·이전 기간 대비·예산 차액·구매 전후 잔액을 계산하고 LLM이 그 근거만 설명한다.

매년 같은 달의 패턴만을 목표로 제한하지 않는다. 미래 지출 전망, 최근 추세와의 차이, 카테고리별 구성,
예산 대비 지출, 구매 후 현금 흐름을 다룬다. 과거 같은 달 기록은 설명 근거 중 하나로 제공한다.
데이터 없이 소비 원인을 추측하거나 구매 안전성·모델 정확도를 보장하지 않는다.

현재 구현된 API와 입력 계약은 AI_SETUP.md, 상세 책임과 계산 규칙은 DESIGN.md를 기준으로 한다.
새 기능을 붙일 때 기존 CRUD와 사용자 주석을 보존한다. 예측·대화 테이블은 필요할 때 추가한다.

프론트는 최근 대화 이력과 기록 시작일·기록 완전성 확인을 전송한다.
NEEDS_CLARIFICATION 응답은 추가 질문으로 표시하고, 원문 질문과 해석한 카테고리·기간을 확인할 수 있게 한다.
LLM 문장에서 숫자를 재추출하지 않고 forecast/budget/purchase 필드로 차트를 만든다.
설정 없음, 기록 부족, 연결 실패와 정상적인 0원을 구분한다. 가짜 모델 예측을 정상 서비스 응답으로 제공하지 않는다.

실제 API 키는 로컬 개인 설정 또는 환경변수로 관리하고 프론트나 소스 저장소에 넣지 않는다.
모델 호출 형식 테스트와 실제 예측 정확도 검증을 구분한다. 실제 이력의 미래 일부를 숨겨
Chronos-2와 단순 주간 반복 예측을 비교하며, 여러 검증 기간에서 유용성을 평가한 뒤 서비스 품질을 주장한다.

다음 단계는 실제 데이터 준비 → 백테스트 → OpenAI 키 설정 후 실제 대화 확인 → 팀원 프론트 연결이다.
